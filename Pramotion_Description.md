# Promotional Forecasting System: Project Overview
*(A simple guide for students and developers to understand the AI brains behind the promotions)*

Welcome! This document explains the **Promotional Forecasting & Optimization** system. It breaks down the complex AI models, the folder structure, the technologies used, and what every piece does in simple, human-readable terms.

---

## 📁 1. The Promotional Folder Structure
The promotional system spans across several distinct folders, connecting user interfaces to a powerful Python AI engine.

### `PythonModels/PromotionForecasting/` (The AI Brain)
This is where the actual intelligence lives. It is a separate microservice written in Python.
*   **`src/api/`**: Contains the API routes (`main.py`, `scenario_routes.py`) that let the Node.js backend "talk" to the Python brain using HTTP requests.
*   **`src/agents/workers/`**: Contains the "AI Employees":
    *   `futurist.py`: The agent responsible for predicting baseline sales (what happens if we do *nothing*).
    *   `marketer.py`: The agent responsible for predicting "Uplift" (extra sales generated by promotions/discounts).
*   **`src/engine/`**: The hardcore math algorithms live here.
    *   `/forecasting/hybrid_model.py`: The Random Forest model that learns from historical sales data.
    *   `/uplift/t_learner.py`: The XGBoost model that measures how sensitive customers are to discounts (Price Elasticity).
*   **`data/`**: Where the raw Excel (`.xlsx`) datasets containing historical sales history are loaded from.
*   **`models/`**: Where the trained AI model files (`.joblib`) are saved so they don't have to relearn everything every time you start the server.

### `PlanogramPlatform/backend/src/controllers/` (The Middleman)
*   `scenarioController.js` & `promotionController.js`: These Node.js files handle requests from the React frontend, format the data, send it to the Python AI, and use **OpenAI** (ChatGPT) to translate the raw math numbers into human-readable strategic narratives (stories).

### `PlanogramPlatform/frontend/src/pages/promotional-forecasting/` (The Face)
*   **`ForecastPage.jsx`**: The UI for projecting overall category revenue. 
*   **`RecommendationsPage.jsx`**: A tool that automatically scans the database to find products that desperately need a promotion to maximize profit.
*   **`ScenarioLab.jsx`**: An interactive sandbox where users can test "What-If" scenarios (e.g., "What happens if I discount Soap by 15% and give it 2 extra facings on the shelf?").

## 🧠 2. The AI Models Used (Academic Overview & Simple Breakdown)

The system relies on a "Dual-Engine" predictive architecture designed to solve two fundamentally different machine learning problems: baseline time-series regression and causal uplift inference. 

Here is a breakdown of exactly what each model does, its inputs, and its outputs.

---

### A. The Baseline Model: `HybridForecaster` (Random Forest Regressor)

**What is it?** 
A Supervised Non-linear Regression model using a "Random Forest".
In simple terms, imagine a dense forest of decision-making trees. Each tree looks at different clues (like the day of the week, the season, the shelf space, the original price) and makes a guess on sales. The forest then mathematically averages all the trees' guesses to provide one highly accurate prediction.

**Why was it chosen?** 
Retail forecasting involves complex interactions (e.g., Ice Cream sells well on Weekends, but only if it's Summer). Random Forests naturally capture these complex relationships without getting confused (overfitting).
*Mathematical Foundation:* An ensemble learning method constructed from a multitude of decision trees at training time. 
$$ \\hat{Y} = \\frac{1}{B} \\sum_{b=1}^{B} f_b(x) $$

**➡️ The Inputs (What we feed the model):**
*   `base_price`: The normal, unpromoted retail price of the product.
*   `facings`: The physical shelf space allocated to the product (how many units are facing the customer).
*   `month` / `day_of_week`: Date and time features to capture seasonal or weekly purchasing habits.
*   `holiday_proximity`: A calculated number indicating how many days away a major retail event (like Vesak or Christmas) is.

**⬅️ The Output (What the model tells us):**
*   **Predicted Baseline Demand ($Y_{base}$):** The expected number of units that will sell on a given day *if we do absolutely nothing* (no promotion, no discount).

---

### B. The Promotion Model: `TLearnerUplift` (XGBoost S-Learner)

**What is it?** 
A Causal Inference (Meta-Learning) model via Extreme Gradient Boosting (XGBoost).
In simple terms, it tries to understand cause-and-effect. It looks beyond normal sales to figure out exactly how much a specific discount *caused* extra people to buy. XGBoost works by building a chain of models, where each new one learns from the mistakes of the last one.

**Why was it chosen?** 
XGBoost is incredible at mapping sharp, sudden changes in behavior, like psychological price barriers (e.g., dropping a price from Rs. 100 to Rs. 99 causes a massive spike in sales that a simple straight-line graph can't predict).
*Mathematical Foundation (S-Learner Framework):* It estimates the causal uplift (CATE, $\\tau$) by predicting two "counterfactual" scenarios (one with a promotion, one without):
$$ \\hat{\\tau}(x) = \\hat{\\mu}(x, T=1) - \\hat{\\mu}(x, T=0) $$

**➡️ The Inputs (What we feed the model):**
*   `promo_discount_pct`: The percentage of the discount we want to test (e.g., 0.15 for 15% off).
*   `promo_type`: The visual type of promotion (e.g., Endcap display, Flyer, Temporary Price Reduction).
*   `category`: The product classification (Staple items like Rice don't change much with discounts, but impulse buys like Chocolate have massive spikes).

**⬅️ The Output (What the model tells us):**
*   **Promotional Uplift ($\\hat{\\tau}$):** The EXACT number of *extra* units we will sell purely because of the promotion. (Total Sales minus Baseline Sales).

## 🛠️ 3. Technologies & Libraries Used

### The Python AI Stack
*   **`scikit-learn`:** A massively popular machine learning library used to build the Random Forest model and scale/normalize data so the AI can understand it.
*   **`xgboost`:** The specialized library used for the high-performance gradient boosting decision trees (the Uplift model).
*   **`pandas` & `numpy`:** The Swiss Army knives of data science. `pandas` is used to load Excel files into "DataFrames" (virtual spreadsheets), and `numpy` is used for ultra-fast heavy math calculations.
*   **`FastAPI`:** A lightning-fast, modern web framework for Python. It turns the AI algorithms into a web server so the Node.js backend can constantly ping it for predictions.
*   **`joblib`:** Used to compress and save the trained AI models to the hard drive so they load instantly when the server restarts.

### The JavaScript (Node.js/React) Stack
*   **`React`:** The frontend library used to build all the interactive dashboards, buttons, and "What-If" forms.
*   **`Recharts`:** The library used to draw the smooth, interactive, staggered "Demand Horizon" line graphs.
*   **`Express.js` (Node):** The backend server that routes data between the React frontend, the MongoDB database, and the Python AI.
*   **`OpenAI SDK`:** Used on the backend to send the raw prediction numbers to a ChatGPT model (`gpt-4`), which then writes a smart, natural-language paragraph explaining *why* the numbers look the way they do (The "Strategic Narrative").
